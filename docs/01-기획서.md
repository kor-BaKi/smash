# 01. 프로젝트 기획서

> 최종 갱신: 2026-11 (Phase 1~3 구현 및 운영 배포 반영)

## 1. 프로젝트 개요

- 서비스명 : SMASH
- 서비스 유형 : 배드민턴 동아리 활동 운영 관리 앱
- 개발 형태 : 개인 프로젝트 (기획·설계·개발·배포·운영 전담)
- 플랫폼 : iOS / Android (Flutter 크로스플랫폼)
- Frontend : Flutter / Riverpod / go_router / Dio / table_calendar
- Backend : Java 21 / Spring Boot 3.5 / Spring Security / Spring Data JPA / Gradle
- DataBase : MariaDB
- 인증 : JWT (Access 30분 / Refresh 180일, Rotation, 서버에는 해시로 저장)
- 푸시 : Firebase Cloud Messaging (data payload로 화면 이동 정보 전달)
- 인프라 : AWS EC2 + Nginx + Let's Encrypt(HTTPS), systemd 서비스, GitHub Actions 자동 배포(main push)
- API : RESTful API (현재 102개 엔드포인트)

### 개발 배경
대학교 배드민턴 동아리 부회장으로 운영을 담당하며 세 가지 구조적 문제를 경험했다.
1. 조 배정·출석 이월·타조 참여·매일 활동 투표 등 고유 운영 규칙을 처리할 전용 도구 부재 → 카카오톡·엑셀 수작업
2. 한 학기 100~250명 신규 부원 모집·가능 요일 취합·조 배정의 대규모 수작업
3. 활동 당일 이동 동행·정산이 조장 수작업에 의존

공통 원인은 운영 규칙과 구성원 데이터를 통합 처리할 전용 체계가 없다는 점이다.

### 프로젝트 목적
배드민턴 동아리 고유 운영 규칙(조 배정, 출석 이월, 타조 참여, 일일 활동 투표)과 운영 데이터를
하나의 플랫폼에서 관리하도록 시스템화하여, 임원의 반복 수작업을 줄이고 데이터 연속성을 확보한다.

## 2. 서비스 소개
- 문제 배경 : 평일 10개 조 편성, 조별 월 4회 보장, 당월 이월 제도, 타조 참여, 매일 투표가 맞물린
  운영 규칙 + 학기 100~250명 신규 모집·조 배정. 전용 도구가 없어 카톡·엑셀·구글폼 수작업.
- 개선 방향 : 매일 투표 생성·출석 이월 계산·타조 집계 자동화 / 신규 모집~배정~활동기록 중앙화 /
  이동 동행·택시 정산·사진·알림까지 활동 당일 흐름을 앱 안에서 처리
- 서비스 가치 : 운영자(반복 업무 감소), 부원(본인 조·활동 직접 확인), 조직(임원 교체에도 데이터 연속)

## 3. 타겟 사용자
### Primary — 임원 (회장/부회장/총무/조장·부조장)
Pain Point : 모집·연락처저장·카톡초대 수작업 / 가능요일 취합·균형 배정 / 매일 투표 생성·집계(월 최대 40개)
/ 이월·충족 수기 계산 오류 / 회비 다단계 취합 / 데이터 분산으로 인수인계 어려움 / 택시비 정산 독촉
Needs : 신규부원 통합관리, 자동 조배정, 투표 자동생성·집계, 충족현황 자동산정, 부원정보 중앙관리, 정산 현황 확인

### Secondary — 부원
Pain Point : 본인 조·활동일 확인 어려움 / 이월·타조 방법 불명확해 조장 문의 / 이동 동행·정산 기록 없음
Needs : 가능요일 제출, 매일 투표 참여(정규·이월·타조·불참), 이월 시 날짜 지정, 본인 소속조·활동 캘린더 확인,
정산 금액·계좌 확인, 푸시 알림

## 4. 문제 정의
기존 운영 방식과 한계:
- 신규 모집 : 구글폼 → 면접 → 연락처 수동저장 → 카톡 초대 (수작업, 누락)
- 조 배정 : 가능요일 별도 취합 → 임원이 10개 조 균형 수동 배정
- 출석·이월 : 임원·조장 수기 계산 (오류 → 신뢰 문제)
- 회비 : 조장 취합 → 총무 엑셀 (행사비 + 체육관비 4주치)
- 이동·정산 : 카톡방에서 호차 편성, 택시비는 결제자가 개별 독촉
- 데이터 분산 : 구글폼·개인기기·메모·엑셀·카톡에 흩어짐 → 인수인계 불가

핵심 문제 : 도구 자체가 아니라, 조 배정~투표~이월~타조~당일이동까지 이어지는 고유 운영 규칙을
통합 처리할 전용 체계가 없어 임원이 여러 도구로 수작업하는 구조가 근본 문제.

## 5. 서비스 목표
운영자 : 반복 수작업 자동화 / 모집·조배정 효율화 / 운영 투명성 / 데이터 연속성
부원 : 운영 규칙 접근성 향상 (소속조·투표·이월을 앱에서 직접) / 활동 참여 편의성

## 7. 보안·운영 방침
- 인증/인가 : stateless JWT, 임원 API는 ROLE_ADMIN 선검증, 본인 식별은 항상 JWT subject에서만 추출
- 비밀번호 : BCrypt / 로그인 5회 실패 시 10분 잠금(429) / 비밀번호 변경·회원 탈퇴 시 현재 비밀번호 재확인
- 민감정보 : 정산 계좌번호 AES-256-GCM 암호화 저장 / Refresh Token은 해시로 저장
- 탈퇴 : 개인정보 삭제 + 계정 익명화(마지막 임원은 탈퇴 불가), 개인정보 처리방침·계정 삭제 안내 페이지 제공
- 파일 업로드 : 확장자가 아닌 파일 시그니처(매직바이트)로 JPG/PNG/GIF/WEBP 검증
- 운영 설정 : Swagger는 운영 환경에서 비활성화, JVM 타임존 Asia/Seoul 고정
- 업로드 사진·시크릿(JWT/DB/암호화 키)은 서버 외부 설정으로 분리하며 저장소에 포함하지 않음
